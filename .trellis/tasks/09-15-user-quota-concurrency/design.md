# 多周期额度与有界并发排队设计

## 1. 设计状态与边界

本设计已随最终方案和容量 10 修订获用户批准。以 `prd.md` 的 R1—R10 为产品契约。保持单任务：存储、准入、DTO、生命周期和前端写集高度重叠，拆独立交付子任务反而增加中间不一致；执行时按核心、接口/界面、验证顺序分批。

本轮对象是单实例、一车一账号的拼车逻辑生成请求，不改 Home 或上游原生限制。模块级共享协调器按稳定 UserID / AuthID 计数，账号策略不能按分配记录 ID 重置。不得从 HTTP 参数读取可信身份、周期或并发令牌。

## 2. 配置和 DTO

- `Membership` 新增可空 `five_hour_limit_nano_usd`、`weekly_limit_nano_usd`，与现有月额度具有相同成员归属和金额解析方式。
- 用户并发策略按 UserID 持久化，账号并发策略按 AuthID 持久化；公开路由继续使用 user/member/account ref，不泄露原始 AuthID。
- 对外金额使用字符串 `five_hour_limit_usd`、`weekly_limit_usd`；并发使用可空正整数 `concurrency_limit`。PATCH 必须区分省略、不限制的 null、合法值，不能因只改周额度将月额度清空。
- 扩展现有成员额度配置和账号编辑路径；用户并发设置写到用户策略，不因换 Key 绕过。具体路由命名沿用已存在的资源结构，不新增平行管理体系。
- 增加 `carpool.concurrency-queue-capacity`，默认 10、正整数校验。容量是整个模块等待者上限，不是每用户复制 10 份，也不是 accounting.QueueSize。配置变更沿用模块既有生命周期规则，不额外承诺热更新。
- 月 `billing` DTO 保持兼容，增加短周期列表，包含周期标识、金额上限、已确认/剩余/超额、实际重置时间、覆盖起点、未知费用与 `pending_sync` 状态。null 不可转换成伪零。

## 3. 持久化与账本

新增递增 SQLite migration，不改 `001`—`003` 内容或 checksum。

建议使用独立短周期账本，而非把 `billing_periods` 强行复用：旧唯一键 `(membership_id, period_from)` 不区分周期，月账期和 retention 仍以旧结构为准。

新增数据职责：

1. 成员短周期配置、稳定用户/账号并发策略。
2. 账号窗口观测：AuthID、窗口类型、有效起止边界、观测时间、窗口版本与覆盖起点；只能来自服务端 auth catalog。
3. 成员短周期累计：成员、AuthID、窗口类型/版本、已确认费用、未知费用计数；有效周期不会因普通明细清理而消失。
4. 可靠费用归属记录：请求可信身份、请求开始时间、AuthID、累计费用及周期关联，支持在周期待同步后补归属；不保留正文、原始 headers 或凭据。不得依赖可能已被用户清理的明细临时 SUM。

`RecordUsageEventBilled` 的同一事务负责事件去重、月累计、短周期/待归属累计及请求金额；事件已存在则全部累计不再增加。费用采用冻结的请求价格，不重新读取当前价格。

同一笔钱参与不同周期限制并不意味着账单相加；请求金额仍只有一份。短周期数据清理必须保护当前窗口、仍可能归属的待同步记录及 in_progress/incomplete 关联；策略不能为节省存储而恢复用户额度。若待归属数据的安全清理范围无法证明，先保留，不静默丢账。

## 4. 账号周期与费用归属

- 读取 `ProjectAccountQuota` 并抽出可复用窗口规范化函数；Claude 显式 5h/7d 可以使用其已知持续时间，Codex 须依据真实窗口分钟数或其他明确协议证据识别，不将任意 primary/secondary 强制映射。
- 优先采用上游绝对重置时间；相对重置时间必须以该响应的观测时间转换，不能用每次页面读取的 now 推迟。
- 使用已知边界且当前尚未结束的窗口，不因展示新鲜度阈值自动禁用。首次未知、到期但尚无下一周期观测时为 `pending_sync`，只跳过对应短周期，保留所有其他门禁。
- 不从已结束边界无限加 5h/7d 模拟上游未来周期。周期重置由可靠新观测确认，不由请求、月账期、页面刷新或重复 headers 触发。
- 同周期重复观测、乱序旧观测和相对秒数舍入不得新建零累计周期。更新边界先合并已有窗口累计；不能仅把精确 reset timestamp 当作清零按钮。当前周期尚未结束时出现边界修订，保留已累计费用。
- 费用归属按真实执行准入时间冻结，而不是入队时间或结算回调时间；长流跨周期仍归原请求窗口，避免写到结算时新窗口。
- 周期待同步期间也保存启用后的可靠费用；新观测确定窗口后按时间范围关联，包含获取首次周期信号的请求，重复关联幂等。不追溯重算旧未计价费用；统计覆盖不足明确显示。
- 账号更换使用新 AuthID 的观测，历史按原账号归档不重写；同一 AuthID 解绑再绑定复用其窗口身份，不可清零。出队发现账号或成员归属已变更则结束该等待请求，要求客户端重试，不把旧授权扩大到新账号。

## 5. 并发协调器

实现放在 `internal/carpool/runtime/`，没有新依赖、定时租约或持久化排队。持有短时互斥锁维护用户计数、账号计数、有限等待队列、幂等请求令牌；不能持锁访问 SQLite、调用上游或等待 channel。

- 仅生成请求使用。入队前鉴权、车/账号范围、当前额度及 writer 健康先检查，已知费用达额不是“等待并发”，不进入队列。
- 两类名额同时可用才能原子取得；不得持有账号名额等用户、或相反。
- 已有等待者时按最早满足条件者放行；可以跳过因自身用户名额不足而阻塞的条目，不允许新来的同组请求反复插队。
- 队列满对新等待者返回安全 HTTP 429 / `concurrency_queue_full`；存在可立即执行且不抢占更早可执行者的请求时不必入队。
- 请求取消或服务关停移除等待者并唤醒必要的后续条目。无需 Sleep 轮询，不设置新增排队/上游超时。
- 调高/取消并发限制触发重新调度，调低不撤销在途名额；降低后的活跃量可以暂时高于新值，只禁止继续超额准入。
- 拿到名额后重查最新数据库授权和金额；失败释放并记录安全原因，不占队列或执行上游。限制更新与名额申请须用策略版本/锁内最新策略复核避免旧值放行。

## 6. HTTP 生命周期与重新授权

`AuthenticatedRequestHook → Control → Store` 保留所有权限与记录职责；需要把前置检查和最终执行准入分开，等待时不持事务。最终请求 ID 及账期开始时间只能创建/绑定一次；队满、取消和出队拒绝也应有可解释的终态，不留下假的永久 in_progress。

队列采用原始请求 context，不能使用 `Background()` 使断开客户端继续排队。出队检查用户禁用、Key 撤销/到期、成员/车辆状态、当前账号 scope、月/短周期、同步记账门禁。不得创建一份旧授权又用另一份新授权计费。

名额覆盖整个 HTTP 逻辑生成生命周期：普通结果、流末尾、错误响应、无效正文、客户端取消均经一次性释放；内部重试和模型映射不释放后重占。利用已有 completion 与 HTTP middleware 安装收尾，注意 middleware 顺序：外层 defer 必须覆盖鉴权成功后所有早退。

不把单次 `ExecutionLifecycle.End` 当作整条用户请求结束。不能只依赖 usage/completion，因为无效正文等路径可能根本不进入执行器。HTTP 结束后异常后台仍继续生产的通用所有权重构不在本轮；保留既有同步记账尾部契约并测试已支持的流路径，不宣称控制所有后台网络并发。

## 7. 状态、错误与隔离

| 场景 | 行为 |
| --- | --- |
| 新增限制未设置 | 该项不限制 |
| 已配置但周期待同步 | 跳过该短周期，DTO 标注待同步 |
| 有效周期已达额 | 上游调用前拒绝，明确是哪一个周期，沿用现有额度错误映射 |
| 并发不足、队列有空间 | 等待，不先写流响应 headers，不调用上游 |
| 队列满 | HTTP 429，稳定队满原因码，不泄露内部计数/其他用户身份 |
| 等待中取消 | 退队，不再执行，不泄漏名额 |
| 出队权限或额度变化 | 按对应授权/额度失败终止，名额归还 |
| writer 故障 | 保留现有 HTTP 503 `accounting_unavailable` |
| 重启 | 活跃计数和等待队列从空开始，历史中断记录沿现有恢复逻辑，已确认费用不丢 |

不新增跨车可见用户信息。用户只能修改原允许的资源；限制配置由管理员执行并沿用审计/同源保护。

## 8. 界面设计约束

读取为：面向管理员与乘客的功能型额度/并发表单，保持现有暖纸色工作台和 `DESIGN.md`。视觉冒险、动效、密度沿用当前值，不新做四方向重设计或资产生成。

功能契约：三秒内分清月/5h/7d 哪一项限制生效、何时重置、是否待同步；管理员可独立编辑且理解空值含义；乘客不会将账号原生百分比误认为自身 USD 用量。

在现有调额表单内增加两项金额和用户并发，账号编辑增加并发；不增加无语义大卡片。额度区域用紧凑分组/列表，覆盖不限、零额度、达额、超额、待同步、未知费用、保存失败和窄屏。原“重置本期”明确限定月用量，不顺带清空短周期。

UI 实施前按 qiaomu-design 功能型界面/打磨路径读取必要参考，保留当前字体、颜色、键盘焦点和 reduced-motion；浏览器完成桌面/移动实际操作验收，不以截图替代数据正确性。

## 9. 兼容、发布与回滚

- 迁移前备份隔离测试库验证升级，用户实际部署提示先备份。不能修改真实 config、auths 或生产数据库做测试。
- 新增限制均为 null，升级不改变现有月额度；新增字段省略的旧请求保持旧行为。
- 如需回滚到不认识新 schema 的版本，停止服务并使用升级前备份，明确备份后的费用不能凭空恢复；不能直接删表宣称安全降级。
- 多账号同时存在不做基准选择；不得默认选 map 中第一个并宣称所有账号周期同步。保持已有请求支持时，新增同步额度应明确未支持/待同步，不绕过已配置的稳定账号并发计数；如实现无法保持此兼容边界，返回规划说明，而不是静默改变范围。
