## 目标

扩展逻辑请求明细筛选和展开，提供可配置保留及独立清理和本期重置操作

## 需求与边界

- 承接父任务 `../09-04-passenger-quota-usage/prd.md` 的 R8 至 R10。
- 记录与设置页面承接 R12 全面重设计，遵循用户选定的 `DESIGN.md`，不套用旧布局。
- 明细一行一个逻辑请求，展开全部 CPA 事件；时间/身份/模型/结果/Token/金额安全可核对。
- 组合筛选和完整 request_id 精确查询，稳定倒序每批 25 条，不伪造重试编号。
- 明细保留默认 90 天，可选 90/180/365/永久；数据库覆盖即时生效，可恢复配置默认。
- 区分明细清理、已结束期汇总删除、本期用量重置；预览、明确后果、确认、有界执行与结果。
- 普通清理可覆盖当前期明细但不能影响金额累计；当前期汇总不能直接删除，重置需审计。
- 不保存正文/原始错误/密钥，不提供全文搜索、CSV 或额外审计清理功能。

## 验收标准

- [ ] 主行计数与事件展开不混淆，所有要求字段与缺失状态正确，真实已确认小计不冒充完整总价。
- [ ] 全部筛选组合、请求/实际模型匹配、精确 request_id、稳定游标及 25 条加载更多通过。
- [ ] 默认/90/180/365/永久、配置回退、重启持久化及即时生效符合需求，审计保留不受误影响。
- [ ] 自动及手动清理只删已完成明细，当前金额、未知数量和拦截状态不变。
- [ ] 结束期汇总单独可删；当前期/在途结算受到保护，删除不会级联删除应保留明细。
- [ ] 本期重置归零已确认累计，保留限额/锚点，审计可核对；在途完成后的新累计如实展示。
- [ ] 预览与执行范围绑定，重复确认幂等，跨期/修订冲突重新预览，批次失败/恢复有实际结果。
- [ ] 管理权限/CSRF/Origin/脱敏测试及桌面/移动完整清理流程通过。
