# 乘客金额配额与用量详情技术设计

## 2026-09-14 用户确认的可靠性简化（优先于历史设计）

用户不接受过多兜底，同意正常同步记账、运行中失败拒绝新生成、缓冲满等待落库；
重启仅标记账务可能不完整，不基于历史 incomplete 全局封锁，不保证崩溃期间精确恢复。
不新增生产者租约树、004 结算迁移、全局容量体系、outbox 或核对解锁功能。具体本轮
边界见金额子任务文档开头；旧设计的更强恢复要求不作为此轮阻断。


## 1. 目标与边界

需求以 `prd.md` 的 R1 至 R12 为准；本文件定义实现契约，不引入充值或余额系统。
沿用 `httpapi -> service -> repository/SQLite`，在 `internal/carpool` 增加独立
`pricing` 与 `billing` 责任边界。前端仍为 Go 内嵌 HTML/CSS/原生 JavaScript。
父任务负责集成，三个子任务的范围与依赖见 `implement.md`。

已有实现和风险证据见 `research/implementation-boundaries.md`；旧数据过渡见
`research/upgrade-transition.md`。SDK 仅增加可选的请求级校验/观察能力，未启用拼车时不执行。

## 2. 数据流

```text
管理员上车/调额 -> 成员限额与账期事务 -> 两端金额进度
乘客 Key -> 原有身份/scope 事务 + 限额检查 -> 固定账期与价格版本
         -> CPA 解析实际执行模型 -> 缺价校验 -> 上游执行
         -> CPA usage.Record -> canonical Token 桶 -> 冻结目录计价
         -> 幂等事件与账期金额同事务 -> 后续请求限额检查/管理明细
CPA Quota.Signals -> 安全窗口投影 -> 同车账号原生配额
清理任务 -> 只删除已完成明细；账期金额保留
```

## 3. 持久化与数值

### 3.1 新增迁移

从 `002_...sql` 起递增，禁止更改 `001_initial.sql`。迁移事务内设置一次性的
`billing_enabled_at`，用于区分新计价请求与旧记录；不是每次启动重新取当前时间。
表名可在实现中按局部惯例细化，以下字段语义不可省略。

| 对象 | 新增字段或事实 | 生命周期 |
| --- | --- | --- |
| `memberships` | 可空 `monthly_limit_nano_usd`、账期时区与原始上车锚点 | `NULL` 仅表示升级旧成员待设置，`0` 是明确零限额；离车不删除 |
| `billing_periods` | 成员 ID、安全成员/车辆快照、UTC 起止、最终限额、已确认金额、未知费用数、重置累计与修订号 | 成员与区间唯一；长期保留，当前期不得直接删除 |
| `proxy_requests` | 账期 ID、冻结目录 hash、计价覆盖起点、计价完成状态；安全 Key/车辆快照 | 跟随明细保留策略，不能级联删除账期 |
| `usage_events` | canonical schema/quality/桶、cache read/write、请求/响应 tier、计价状态/原因、实际价格项/单价/费用 | 复用原 `event_id` 幂等；旧行状态为 `legacy_unpriced` |
| 价格目录 | 内容 hash、有效 JSON、来源、成功更新时间、当前版本指针 | 更新先完整校验后原子替换；在途请求可继续引用旧版本 |
| 数据设置 | `usage_retention_days` 数据库覆盖值、计价启用时间 | 缺失覆盖值表示使用配置默认，`0` 表示永久 |
| 清理作业 | 操作类型、冻结范围/上限、状态、计数、游标、执行者与确认引用 | 分批恢复、重复执行不扩大目标范围，结果可查询 |

采用 SQLite `INTEGER` 保存 nano-USD，`1 USD = 10^9 nano-USD`。输入和 API 金额均为
十进制字符串，不能经过 JS `Number` 或 Go `float64` 再比较。单价用 `json.Number` 解码为
精确十进制/有理数，先乘 Token、按事件求和，再一次四舍五入至 nano-USD；汇总只加整数。
输入最多 9 位小数且不得超过可存储范围，拒绝空值、负数、NaN、Infinity、溢出和多余精度。
展示可以缩短小数，但非零小额不能看起来是免费；详情保留精确值。相等边界按存储值判断。

### 3.2 账期

`billing` 提供纯函数，以原上车时刻及其报表时区计算每个月的周年边界；按原始日号计算，
31 日截至 2 月月末后，下个月仍回到 31 日，不能从上个月的截短日期反复 `AddDate`。
首期不早于实际上车时刻。存储 UTC `[from,to)`，每次请求固定账期，跨月结束及迟到用量仍
归请求开始所属期。时区与锚点保存为成员关系事实，不因调额或服务器重启改写历史边界。
夏令时缺失/重复本地时刻必须采用一致规则并有确定性测试，生成的 UTC 边界严格递增。

新请求、报表读取及维护流程调用同一账期解析器；不依赖某一分钟定时任务必须恰好运行。
需要展示的空账期按需物化，不能在 HTTP 请求中无界补齐多年数据。离车终止新授权，旧期仍
可接收已经开始请求的用量；换车必须创建新成员关系和新限额。

### 3.3 调额与重置

调额在单事务中更新当前成员限额、当前期最终限额和成功审计，保留费用和锚点。
后续请求不读有延迟的限额缓存；管理保存成功后两端重新读取相同 DTO。

重置只抵消事务提交时已经确认的本期金额与未知累计，保留明细原始费用及重置审计。
之后到达的实际用量仍正常记账，不能因为 `event_id` 重放把重置前金额恢复。
采用累计总值与重置基线（或等价的修订事实）计算有效已用额，审计保存前值、抵消值及期 ID。
预览包含本期在途请求数，确认页说明在途请求完成后可能再次增加用量。

## 4. 价格目录与计价

### 4.1 目录加载

内置带来源说明的 LiteLLM JSON 快照，参考同级 `sub2api` 的数据结构和计价维度。
默认远程地址采用 LiteLLM 原始目录
`https://raw.githubusercontent.com/BerriAI/litellm/main/model_prices_and_context_window.json`，
配置项 `carpool.pricing.catalog-url` 可替换为管理员控制的镜像，默认每日检查一次。
不直接运行或复制 LGPL-3.0 价格业务代码，也不在前端下载目录。

读取完整且有大小上限的响应，校验 HTTP 状态、JSON 结构、有效模型价格、非负有限单价和
内容 hash；有配置校验值时同时验证。内容 hash 是版本标识，不冒充来源签名。
使用 HTTPS URL 与标准 URL 解析，禁止 URL userinfo，日志不泄漏 query 中的秘密。
下载、解析、校验、缓存持久化失败均保留最后有效版本并更新安全失败状态。
后台更新由模块生命周期 context 取消，不给已建立连接增加网络超时。

配置加载同步覆盖 `internal/config/carpool.go`、配置序列化/克隆消费者、测试和
`config.example.yaml`。首次离线启动使用内置目录；已有缓存优先采用最后有效目录。
当前版本切换为原子操作；请求在授权时固定目录引用/hash，后续重试也用同一目录。
事件保存实际单价和费用后，无需依靠永久保留所有旧目录才能解释历史金额。

### 4.2 模型与价目匹配

只使用 CPA 确定的实际模型、明确 provider 命名空间和已知别名关系。复用已有 suffix/
模型别名解析结果，不复制另一套 thinking 解析，不做相似字符串猜价。
在 CPA 最终模型解析和插件改写后、每次实际执行前调用可选的请求级价格校验器；覆盖流式、
非流式、模型池、mixed provider、pinned/affinity、401 刷新与插件执行路径。
对缺价候选必须返回可识别本地错误，不能连接该上游、进入账号冷却或静默落到范围外账号。
若请求前面已有实际尝试，保留其已发生费用与真实结果，不能为了缺价错误擦掉此前事件。

校验器属于服务器持有的请求 context，不能来自客户端 header/JSON，插件不能删掉它。
SDK 的可选接口仅携带模型/格式/tier 等必要数据，业务目录由拼车模块闭包持有；无拼车
snapshot 时该能力为 no-op。模型查询不检查金额或价格，但仍经过原有车辆与 scope 授权。

### 4.3 计价规则与缺失

调用 `EnsureTokenBreakdownForProvider`，使用互斥的 uncached input、cache read、
cache write、non-reasoning output、reasoning 桶。输出已包含 reasoning 时不能再加一次；
目录没有独立推理价时，推理按所属输出单价计算并明确记录该依据。
实际 tier 优先使用 CPA 的响应 tier，再使用有确定语义的请求 tier；`auto` 不能被当成付费
priority。支持目录显式基础、缓存、tier、长上下文档位，长上下文阈值按 canonical 输入总量。
同一维度多种修饰价格没有可验证组合时不得自行乘一个倍率。

必要价目缺失在可预知阶段拒绝；连接后才发现的 Token 不完整、schema 矛盾、实际模型与
可确认价格映射不符、差异价格所需的缓存 TTL/多模态拆分缺失，记 `unknown` 和安全原因。
不因 failed 标记把真实 Token 费用抹成零。没有必要额外维度的明确零 Token 可计为已知零。
允许路由的多模态及工具附加费不能据路由名称臆测为完整 Token 费用；未覆盖部分明确未知。
本期继续按已确认金额拦截，未知数量和不完整覆盖同时显示。

## 5. 可靠用量、请求授权与错误

CPA 的 `usage.Record` 是唯一用量来源。为拼车 context 增加同步观察入口，在全局异步
分发前消费相同 Record，复用现有计量而非重新读取正文。拼车金额不能走会丢弃的 writer
队列；旧全局 Key 的统计及插件分发保持原行为。重复分发按 `event_id` 不重复收费。

事件安全映射、计价、事件插入、期累计更新同事务提交；不得先扣费用后记录明细，或先写
明细再异步改限额。取消请求后仍完成已产生事件的持久化；不使用已取消的网络 context 丢失
账单，也不额外限制已建立上游连接的持续时间。仅持久化白名单字段，不保存 `Record.APIKey`、
`Fail.Body`、`Source` 中的凭据、原始 headers 等内容。

记账存储失败标记服务记账健康异常，阻止后续新生成请求并报告 `503`，不能声称费用为零；
恢复需完成失败记录重试或启动恢复核对，不能只因为重试定时器触发就清除异常。
启动时处理未完成逻辑请求和计价覆盖缺口为 `incomplete`/未知，不捏造上游事件或重试编号。
同步/异步入口、请求 completion 的先后关系、关闭排空和重复投递均需回归测试。

| 条件 | HTTP/安全错误码 | 结果 |
| --- | --- | --- |
| 未设置限额 | `403 quota_not_configured` | 记录一次本地 rejected 事实，不连接上游 |
| `$0` 或已用大于等于限额 | `403 quota_exhausted` | 立即拒绝后续新生成；不影响已放行请求 |
| 实际计价模型无价 | `422 model_price_not_configured` | 本地拒绝；该执行不连接上游 |
| 必要计价数据缺失 | 维持实际请求结果，`pricing_status=unknown` | 保留已知 Token，提示费用统计不完整 |
| 记账不可用/SQLite 忙 | `503 accounting_unavailable` / 现有忙错误 | 不在持久化状态未知时继续放行 |

新增错误必须贯穿 `domain -> service -> sdk/access/handler -> 客户端`，不能继续统一变成
“Carpool request is not authorized”而丢失原因；只在受控类型携带固定安全 code。
请求元数据只解析 model/stream 等必要字段，不保存正文，不妨碍后续协议 handler 读取请求。
拒绝发生太早而字段确实不可取得时返回缺失，不猜测模型。

## 6. 浏览器 API

全部浏览器路径相对 `/carpool/api/v1`。沿用角色/改密门禁；写操作沿用 Origin、CSRF、
审计事务。DTO 显式构造，金额为字符串，缺失为 `null`，日期为 UTC RFC3339。

| API | 契约 |
| --- | --- |
| `GET /me/car` | 增加本人当前 `billing`，无车维持 `car:null` |
| `GET /me/members/usage` | 保留原 period Token 报表；每个当前成员增加独立月度 `billing`，不将今日/7d/30d 当限额期 |
| `GET /me/accounts` | 增加 `quota` 投影，继续只返回当前车已分配账号 |
| `POST /admin/cars/:car_ref/members` | 必填 `monthly_limit_usd` 字符串，上车/换车与限额同事务 |
| `PATCH /admin/cars/:car_ref/members/:member_ref/quota` | 调整 `monthly_limit_usd`，不调用换车方法 |
| `GET /admin/cars/:car_ref/members` | 增加同构 `billing`，可补设升级旧成员限额 |
| `GET /admin/billing/periods` | 按成员/车辆/时间查看精简账期历史与重置后累计，稳定分页 |
| `GET /admin/pricing` | 版本 hash、来源标识、最近成功、最近检查、安全失败原因 |
| `GET /admin/usage/requests` | 按 R8 筛选，25 个逻辑请求主行，返回 `next_cursor` |
| `GET /admin/usage/requests/:request_id` | 安全主行与全部关联上游事件，无虚构 retry number |
| `GET/PATCH /admin/retention` | 当前值、配置默认值、生效来源；`null` 恢复配置，`0/90/180/365` 为页面覆盖值 |
| `POST /admin/retention/preview` | 操作类型、明确范围；返回预览数量、在途数量及一次确认引用 |
| `POST /admin/retention/jobs` | 确认引用与匹配操作，服务端再次授权后执行有界作业 |
| `GET /admin/retention/jobs/:job_id` | 范围、运行状态、实际删除数量/失败，支持刷新后恢复 |

`billing` 含 `currency=USD`、`status`、`limit_usd`、`confirmed_usd`、`remaining_usd`、
`overage_usd`、`usage_percent`、`unknown_cost_events`、`data_complete`、`period_from`、
`period_to`、`timezone`、`coverage_from`。进度由后端用同一整数账本派生；`$0` 分母及未设置
限额时 `usage_percent=null`，用状态表示，不产生 Infinity/NaN。超额比例可以大于 100。
离车历史仍按原 Token 报表可见范围处理，但不能把旧车账本混入新车当前成员金额。

`quota` 含 `supported`、`observed_at`、`stale`、`windows[]`；窗口只含受控 `id/label`、
`used_percent`、`reset_at`、`window_minutes`、`status`。不直接公开 `Signals`。
Claude 的独立短/长窗口、Codex primary/secondary 优先，其余按稳定键排序；状态-only 窗口
也可见。相对 reset 秒数以观测时刻换算，不能以页面刷新时刻不断延后。quota 陈旧性与账号
健康陈旧性独立计算，账号刷新不能把老配额变成新配额。复用 CPA 既有解析器；缺少结构化
投影时在 `carpool/runtime` 增加一个投影函数，不新增上游探测调用。

## 7. 明细查询与保留

主行以 `proxy_requests` 为基表；账号/实际模型筛选使用 `EXISTS` 或先聚合事件，避免 JOIN
放大请求数。所有已选筛选条件 AND 组合，模型条件内部匹配请求模型或任一真实事件模型。
排序为 `(started_at DESC, request_id DESC)`；游标编码版本、筛选摘要、时间范围上界和末项键，
更换筛选必须重置游标。拒绝畸形游标及与筛选不符的游标，不使用 offset。
首次查询固定时间上界，后续加载不因新请求插入而重复；运行中的结果会变化，刷新后重新查询。

请求总金额保留已确认小计及未知数量；只要含未知事件就不能把小计标成完整总价。
计价状态至少含 `priced`、`unknown`、`price_missing`、`legacy_unpriced`、`not_billable`、
`pending`。主行仍保留原 outcome；缺价是计价/拒绝原因，不混作上游 HTTP 失败。
缺数据文案根据来源区分“上游未提供”“历史记录未计价”“尚未完成”。

保留设置以数据库覆盖优先，缺失覆盖才读配置。页面只提供 90/180/365/永久，配置的已有
合法自定义正值仍兼容并注明“配置默认”；默认仍 90 天。配置支持显式 0 永久，省略字段继续
默认 90，不能被默认值填充误覆盖。审计保留仍使用原 `audit-retention-days`，不随明细永久
设置改变，也不纳入本次明细清理按钮。

普通清理不能删除 `in_progress` 或尚未完成记账的请求。按逻辑请求冻结范围和高水位，
用有界事件/请求批次完成删除；批次中途保留状态，避免已删的部分事件又导致主行金额下降。
请求层保留最终计价小计/完整性快照，直至该请求明细整体删除。保留汇总金额、未知数量和
账期信息。迟到事件不能使已删除历史复活或再次计费；确认完成并排空后才可删除明细。

三种作业分别是 `usage_details`、`closed_periods`、`reset_current_period`。
删除已结束期需再次校验期结束且无在途结算；删除汇总后，仍保留的请求明细只能引用可空
关联/冻结账期快照，不能阻止合法删除，也不能重新生成已删汇总。
本期重置校验同一期 ID/修订号，跨月或调额导致预览失效时要求重做预览，返回冲突而不重置
另一期。作业确认幂等、范围不可扩大，有成功/失败审计及实际数量，不提供无界同步 DELETE。

## 8. 界面设计锚

读取为面向管理员和乘客的中文日常工作台，围绕额度判断与费用核查重新组织导航及信息层级。
2026-09-05 用户要求彻底重设计：旧 `app.css` 配色、232px 深色侧栏、四统计卡及原布局

## 9. 兼容、发布与回滚

升级先停服务并使用既有 carpool 备份命令，保留原数据库、配置和可执行版本。只在全套新版本
就绪后执行迁移；不在生产启动一半完成的金额实现。迁移不追溯计价，旧成员限额为 `NULL`，

价格目录失败使用旧目录，不能通过关闭 carpool 或绕过用户 Key 授权来恢复请求。

新 schema 不能承诺直接用旧二进制打开。回滚需停服务，选择恢复升级前备份或发布前向修复；
恢复备份会失去升级后业务记录，执行前必须另行确认。开发验证仅使用隔离数据库和假上游。
