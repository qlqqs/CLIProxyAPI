## 4. 命令与浏览器证据

子任务按影响范围先执行定向测试。最终至少执行以下命令，记录实际输出与失败原因：

```bash
gofmt -w .
go vet ./...
go test ./...
go test -race ./internal/carpool/...
go test -race ./sdk/cliproxy/usage ./sdk/cliproxy/auth ./sdk/api/handlers/...
node --check internal/carpool/web/assets/app.js
go build -o test-output ./cmd/server
CGO_ENABLED=0 go build -o test-output-nocgo ./cmd/server
```

构建前先确认 `test-output` 和 `test-output-nocgo` 不属于用户已有文件；若存在，改用经确认
不存在的测试输出路径。通过后只删除本轮生成的测试二进制，不清理用户目录或线上数据。
完整 `go test ./...` 或 race 失败不能因定向测试通过而忽略，区分已有问题与新增回归并报告。

浏览器使用隔离 SQLite、测试管理员/乘客、假 CPA 数据。沿用 Go 服务，无需 Node 构建；
实际使用的端口先检查占用，完成实现后给用户可访问的 `/carpool/` URL。
以 Playwright 保存桌面 1440x900、移动 390x844（并检查 360px 窄屏）截图及交互记录；
检查实际文字边界、整页水平溢出、键盘焦点、对话框滚动、200% 放大和状态刷新。
不把 mock 数据截图当成真实上游费用证据；测试 fake upstream 是为了验证相同数据流。
