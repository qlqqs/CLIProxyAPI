# 乘客改密说明与账号原生配额展示

## 目标

保留改密门禁并解释数据仍在，按 CPA 原生窗口展示账号配额和缺失状态

## 需求与边界

- 承接父任务 `../09-04-passenger-quota-usage/prd.md` 的 R1、R7 和共同安全约束。
- 保留强制改密门禁，说明管理员重置原因、业务数据仍保留、改密后重新登录。
- 账号用量复用 CPA 原生快照，多窗口互不合并，前两个直接显示，其余可展开。
- 缺失显示“上游未提供”，没有百分比只显示真实状态，陈旧快照明确标记。
- 承接 R12 所选设计系统、全局导航、登录/改密及全部现有基础页面重设计；保留中文与同车
  范围，不保留旧样式和布局，不新增主动上游配额查询、金额账本或清理功能。

## 验收标准

- [ ] 选定设计覆盖新全局壳及全部现有基础页面，旧功能可达，后续页面遵循同一 `DESIGN.md`。
- [ ] 重置后旧会话失效；临时密码登录只可改密与退出，页面说明车辆/用量/API Key 未删除。
- [ ] 改密并重新登录后恢复原业务数据；首次创建账号及主动改密不会错误提示管理员重置。
- [ ] Claude/Codex 多窗口独立展示，两个主要窗口直显，其余可键盘展开。
- [ ] 缺快照、部分字段缺失、状态-only、非法 signal、5 分钟陈旧及上游重置时间正确。
- [ ] DTO 仅含安全配额投影；不同车辆的乘客不能读取彼此账号或配额。
- [ ] 桌面/移动实际浏览器流程通过，长标签、展开刷新与空态没有重叠或假百分比。

## 依赖

- 无金额账本业务依赖，父任务最终规划批准后作为首项实施。
- 后续 `09-05-passenger-billing` 会修改共享前端及 API，必须保留本项实现。
- 本子任务独立通过检查不代表父任务全部完成；设计与执行分别见本目录 `design.md`、`implement.md`。
