# 5h / 7d 本地滚动额度技术设计

## 1. 设计边界

本任务将 Carpool 当前“月账期 + 上游同步短周期”模型替换为直接对标 Sub2API 的本地 5h / 7d 用户额度。对标行为，不复制 Sub2API 的 Vue、PostgreSQL 浮点金额、每 Key 归属、1d 限额或总额度。

稳定归属仍为 `UserID` / 当前成员关系：同一乘客的全部 Carpool API Key 共享额度。账号原生 CPA 配额继续作为账号状态展示，不参与用户额度窗口。

## 2. 数据模型与迁移

### 活跃字段

- 成员保留 `five_hour_limit_nano_usd` 与 `weekly_limit_nano_usd`，非空整数：`0` 表示不限，正数表示限额。
- 新增或调整用户本地额度窗口状态，至少包含：成员/稳定用户身份、窗口种类、窗口起点、已确认 nano-USD、未知费用计数和更新时间。
- 5h 窗口起点为首笔可靠费用时间；7d 起点为该时间在报表时区的当天起点，结束分别为 `+5h` 与 `+7d`。

### 遗留字段

- `memberships.monthly_limit_nano_usd`、`billing_periods` 与历史月累计不物理删除，保证旧库升级和回滚取证。
- 活跃代码不再创建新月账期、不再更新月累计、不再用月额度准入、不再向浏览器 API 输出月额度。
- 新迁移只能增加或转化 5h/7d 本地状态，不能改写既有迁移 checksum；实施时以工作区实际下一个空闲版本号为准，避开当前并行新增的 `005_api_key_tokens.sql`。

### 现有短周期账本

优先复用 `quota_request_fees`、`billed_event_receipts` 和当前额度累计表的可靠去重能力，但移除对上游 `AuthID` 窗口观测的依赖。若现有唯一键无法表达用户本地窗口，新增递增迁移建立专用本地窗口表，不强行复用错误语义。

升级时保留当前仍有效的 5h/7d 已确认累计；若旧记录只能绑定上游窗口且无法可靠映射到本地窗口，则以可证明的起止时间迁移，不能猜测。无法证明的旧累计保守保留到首次显式重置或窗口自然到期，并在实现研究中记录转换规则。

## 3. 限额写入合同

- 创建成员请求改为 `five_hour_limit_usd`、`weekly_limit_usd`；两项必须出现并接受 `"0"` 表示不限。
- 成员额度 PATCH 保留部分更新：省略字段保持原值；`null` 不再作为不限入口；`"0"` 是唯一不限值。
- `concurrency_limit` 继续接受正整数或 `null` 表示不限，和金额语义分开。
- 旧 `monthly_limit_usd` 不进入领域更新；为保持旧客户端请求可解析，多传时忽略该遗留字段，但响应不再返回它，且任何值都不能重新启用月额度。

## 4. 窗口与准入

### 有效窗口

- 读取窗口时先用注入时钟判断是否到期；已到期窗口投影为已用 0、无活跃重置时间，直到下一笔可靠费用建立新窗口。
- 准入前读取 5h/7d 当前有效用量。限额为 0 时跳过；正数且已用 `>= limit` 时拒绝。
- 排队请求出队后必须重新读取两个窗口，防止等待期间达额或管理员调低限额。

### 费用落账

- 请求费用仍以冻结价格和可靠 usage 事件为准。
- 同一事务/幂等事件中更新请求费用、5h 用量和 7d 用量；一个事件只能增加一次账单金额。
- 窗口为空或已过期时，以本次费用建立新窗口；否则累加当前窗口。
- 已开始请求不因后续达额中断，允许最后一笔产生超额；下一请求拒绝。
- 未知费用只增加未知计数，不伪造金额；不因未知金额自动阻断。

## 5. API 投影

统一输出两个窗口：

```json
{
  "five_hour_limit_usd": "10",
  "weekly_limit_usd": "50",
  "quota_windows": [
    {
      "kind": "5h",
      "limit_usd": "10",
      "used_usd": "2.5",
      "remaining_usd": "7.5",
      "status": "active",
      "period_from": "...",
      "reset_at": "..."
    },
    {
      "kind": "7d",
      "limit_usd": "50",
      "used_usd": "2.5",
      "remaining_usd": "47.5",
      "status": "active",
      "period_from": "...",
      "reset_at": "..."
    }
  ]
}
```

- 限额 0：状态 `unlimited`，显示“不限”，仍可显示已确认用量，但不显示剩余金额。
- 尚未开始：状态 `not_started`，已用为 `0`，`period_from/reset_at` 为 null，UI 说明首次使用后计时。
- 达额/超额：分别使用 `exhausted` / `overage`，剩余不小于 0，超额单独返回。
- 移除当前用户 API 的月 `billing` 主投影；历史管理接口如需保留必须标明历史，不供当前概览消费。

## 6. 界面转译

### 乘客概览

- 主视觉读数改为“7 天剩余额度”。
- 正常状态显示剩余金额；不限显示“不限”；未开始显示完整限额并说明“首次使用后开始计时”。
- 同一区域显示已用/上限、进度、重置时间与状态；5h 作为次级窗口。
- 删除“月账期与统计”“月额度重置”等月度信息，保留报表时区与费用统计说明中仍有意义的内容。

### 成员用量

- 每行只渲染 5h 与 7d，延续现有紧凑窗口布局。
- 保留上一轮已完成的独立并发列及 Sub2API 风格并发徽标。
- 已离车成员没有当前限制时显示历史用量统计，不伪造当前额度。

### 管理端

- 加入成员表单提供 5h 与 7d 两个金额输入，默认 `0`。
- 调额弹层仅保留 5h、7d 和用户并发。
- 数据保留页删除月度重置，改为“重置 5h / 7d 用量”；确认文案明确不修改限额、不删除历史请求费用。

当前设计系统、暖纸色、系统中文字体、表格横向局部滚动、原生进度与无内联样式约束保持不变。直接对标 Sub2API 的信息结构，不复制其视觉品牌。

## 7. 兼容与回滚

- 升级前使用隔离 SQLite 复制库验证迁移；不触碰当前 `8317` 实例与真实账号。
- 产品回滚优先恢复升级前数据库备份；遗留月字段仍在，因此旧版本可以读取旧历史结构，但升级后新产生的 5h/7d 用量不会自动回填月累计。
- 发布后不再承诺月额度准入；回滚到旧版本前必须明确旧月数据已停更。
- 当前未提交的并发列改动视为工作区基线，实施与提交时保留。
