# 移除月额度并直接对标 Sub2API 5h / 7d 额度

## 目标

将 Carpool 成员额度从“月度 + 5 小时 + 7 天”收敛为仅保留 **5 小时额度**与 **7 天额度**，并直接对标 Sub2API 的本地滚动 USD 限额模型。乘客概览以 7 天剩余额度为主，管理端、准入、记账、接口和展示使用同一套 5h / 7d 逻辑。

## 背景与已确认事实

- 当前成员关系、创建成员表单、成员额度 PATCH、授权准入、月账期汇总、乘客概览、成员用量表和数据保留页面都依赖 `monthly_limit_usd` / `MonthlyLimitNanoUSD` / `billing_periods`。
- 当前 5h/7d 额度跟随上游账号观测窗口，存在 `pending_sync`；Sub2API 则使用本地确定性滚动窗口、独立已用金额与重置时间。
- 用户明确要求“直接对标 Sub2API”，但只保留 5h 与 7d，不引入 Sub2API 的 1d、Key 总额度、余额或订阅。
- 当前工作区已有上一轮未提交的成员用量“并发独立列”改动。本任务必须保留这些改动，不得覆盖或回退。
- 详细对标证据见 `research/sub2api-benchmark.md`。

## 范围内需求

### R1：产品界面只保留 5h 与 7d 额度

- 管理员创建/加入成员时直接配置 5 小时额度与 7 天额度，不再出现或提交月度额度字段。
- 管理员调整成员额度时只显示并独立编辑 5 小时额度、7 天额度与用户并发。
- 乘客成员用量页面只显示 5h 与 7d 两个额度窗口，不再出现“本月”“月额度”“月度额度”或月额度进度。
- 面向用户的提示、错误、说明和危险操作不得继续把月额度描述为有效限制。

### R2：对标 Sub2API 的 5h / 7d 本地滚动额度

- 每名 Carpool 用户共享一组 5h / 7d 限额与用量，其全部 Carpool API Key 不能绕过限制。
- 额度使用 nano-USD 精确持久化；公开 API 继续使用十进制 USD 字符串，避免浮点金额。
- 限额 `0` 对标 Sub2API 表示不限；正数表示限额；负数、空字符串、非法小数和溢出值拒绝。
- 5h 窗口从首次产生可靠计费的请求时刻开始，持续 5 小时；7d 窗口从首次产生可靠计费的当天起点开始，持续 7 天。
- 窗口到期后有效用量归零；下一笔可靠费用建立新窗口并成为新窗口首笔用量。
- 准入时若有效已用金额已达到限额，则在调用上游前分别返回稳定的 `five_hour_quota_exhausted` / `weekly_quota_exhausted`。
- 已经获准的请求可以使实际用量略微超额，不中断在途请求；后续请求被拒绝，与 Sub2API 行为一致。
- 同一笔可靠费用同时累计到 5h 与 7d，但账单金额只记一次，不发生双倍计费。

### R3：乘客概览以 7 天剩余额度为主

- 将“本月剩余额度”改为“7 天剩余额度”。
- 主金额、额度上限、已确认用量、超额/已用尽状态与重置时间均来自本地 7d 用户额度窗口。
- 7d 限额为 0 时显示“不限”；尚未产生首笔可靠费用时显示完整限额与“首次使用后开始计时”，不得伪造已用金额或重置时间。
- 7d 已用尽/超额时，概览给出与实际 7d 准入行为一致的警告。
- 概览同时保留 5h 窗口作为次级额度信息。

### R4：接口、存储与历史兼容

- 浏览器 API、服务 DTO、领域模型、SQLite 访问和测试不再要求管理员提供月额度才能创建成员。
- 当前 API 不再输出或主动写入 `monthly_limit_usd` / 月 `billing`；旧客户端多传的遗留字段不影响 5h/7d 设置，也不能重新启用月额度。
- 旧 SQLite 的月额度列、`billing_periods` 和历史账期数据保留为只读兼容数据，不做破坏性删列迁移；它们不再影响新请求、当前展示或额度重置。
- 旧数据库升级必须可启动，现有成员、5h/7d 配置、可靠费用账本、并发策略和历史请求不得丢失。
- 数据保留页面与后端删除“重置本月用量”；提供对标 Sub2API 的“重置 5h / 7d 用量”操作，明确同时清零两项用量并让后续首笔费用重新开始窗口。

## 范围外

- 不引入 Sub2API 的 1d 限额、Key 总额度、余额、订阅、支付或兑换码体系。
- 不改变账号原生 CPA 配额的展示与含义。
- 不改变用户/账号并发排队算法、队列容量或释放生命周期。
- 不新增分布式额度、网络超时或多账号窗口协调。
- 不修改 Home、非 Carpool 用户 Key 或 translator 体系。

## 验收标准

- [ ] 创建成员无需月额度，可配置 5h 与 7d；两项均为 0 时代表不限。
- [ ] 管理员额度编辑仅包含 5h、7d 和用户并发，保存任一字段不会意外修改其他字段。
- [ ] 乘客概览标题为“7 天剩余额度”，所有金额、状态和重置时间来自本地 7d 窗口。
- [ ] 尚未开始、正常、接近限额、已用尽、超额、窗口到期与不限状态均有确定显示，不出现 `pending_sync` 或伪造重置时间。
- [ ] 成员用量每行仅显示 5h 与 7d 两个用户额度窗口，并保留上一轮新增的独立并发列。
- [ ] 月额度不再参与授权或出队复核；5h/7d 达额仍在上游调用前拒绝。
- [ ] 5h 从首笔用量时刻起 5 小时，7d 从首笔用量当天起 7 天；过期后下一笔费用正确建立新窗口。
- [ ] 重置操作同时清零 5h/7d 用量和窗口起点，不修改限额、并发、历史请求费用或账号原生配额。
- [ ] 面向用户的页面和提示中不再出现有效“本月/月度额度”概念。
- [ ] 旧 SQLite 数据库升级后可读取，遗留月数据不影响当前逻辑，现有 5h/7d 配置与可靠费用累计不丢失。
- [ ] 受影响的 Go、Node、HTTP 集成和浏览器桌面/移动验收通过，必需编译检查通过。

## 约束与风险

- 该变更跨越数据库、领域模型、授权准入、记账、HTTP DTO、管理表单、乘客页面、保留操作与测试，属于复杂跨层改动。
- SQLite 已发布迁移不可修改；新增本地窗口状态必须通过递增迁移或安全复用现有表实现。
- Carpool 金额继续使用 nano-USD，不能照搬 Sub2API 的浮点存储。
- 直接对标的是 5h/7d 行为与信息层级，不复制 Sub2API 技术栈、品牌样式或每 Key 归属；Carpool 仍按稳定用户共享限制。
- 不得回退当前工作区已有的成员并发独立列改动。
